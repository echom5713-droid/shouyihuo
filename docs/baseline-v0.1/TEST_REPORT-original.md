## 业务规则验证：25 项单元测试

- 三个案例均完成正确操作路径，得到 100 分且必要验证通过；供水阀关闭案例不要求更换零件。
- 正常、持续失水、到达溢流位置和无法补水的状态可区分；时间步长与评分可重复。
- 未诊断不能直接恢复供水完成处理；观察、检查和安全隔离不要求统一先诊断或关水。
- 非法拆卸记录关键安全错误，装配状态不改变；仅关水不清除故障；漏做隔离确认仍不能拆卸。
- 更换错误组件不清除真实故障；漏装组件时阻止恢复供水；未复测即使达到 80 分也不能合格。
- 复测中阻止改变工作状态，仍允许观察；通过后再次改变工作状态会使验证失效。
- 关键安全错误使 100 分记录仍不合格，刷新数据往返不会清除错误。
- 独立测评锁定首次诊断；重复检查、重复诊断、重复复测和归档不增加成绩或记录数量。
- 引导训练重试保留首次错误；结构认知不归档成绩、不能合格或获得证明。
- 结束记录不可变，新尝试使用新编号；不同模式存储隔离。
- 损坏 JSON、不兼容版本、缺失字段、非法嵌套状态均受 schema 校验保护；读写失败有可恢复结果。
- 清空操作只删除本项目 key，保留其他项目数据。

## WebGL 画面与桌面尺寸验证

- 实际生成非空三维水箱并检查截图：有可见空腔、外壳、箱盖、供水阀、连管、进水组件、浮球、密封翻板、溢流管与透明水体。
- 测试直接点击 Canvas 上的进水组件网格，确认事件来源为 `model`，右侧说明和部件列表同步选中进水组件。
- 水箱排空前后分别截图，实际检查到水体消退、浮球下降、供水阀手柄方向改变，而非仅文字读数变化。
- 爆炸视图实际呈现部件分离，但业务装配标志仍保持已装配，不能借此完成拆装流程。
- 1440×900 和 1280×800 下检查入口、实训与报告；主要按钮可见，没有水平溢出。
- 安全提示固定在操作面板下方，独立测评也保留；诊断根因解释只在提交后或报告中出现。
- 开发完整流程与生产预览均记录请求，没有发现外部 HTTP 课程资源、字体、模型或接口请求。开发时 Vite HMR 连接仅指向本地服务。
- 正常流程未发现页面级 JavaScript 异常。依赖存在 `THREE.Clock` 弃用提示，构建存在 Three 分包体积提示，两者不影响本次通过的验证。
