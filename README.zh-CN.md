## 1. 获取源码与启动

下载并完整解压源码 ZIP，进入含有 `package.json` 的工程文件夹。GitHub 下载的 ZIP 可能使用仓库名和分支名作为文件夹名。不要直接双击 `index.html`；应用需要通过本地服务器打开。

这次开发、安装、测试均在云端 Linux 中完成。云端的 `127.0.0.1` **不是你的电脑**，也不是公开网站。将源码下载到电脑并执行下面命令后，浏览器访问的才是你自己的本机服务。

建议使用 Node.js 24 系列；本次实际测试 **Node v24.19.0、npm 11.9.0**。本次 UI 升级没有升级依赖；项目继续采用精确版本，并包含 `package-lock.json`。也允许符合 `package.json` engines 的 Node 版本，但其他版本没有逐一测试。

### Windows PowerShell 首次启动

1. 安装 Node.js 24。若电脑已有 Node，可以先查看下面的版本命令。
2. 在文件资源管理器中打开解压后的文件夹，继续进入，直到能看到 **`package.json`**。Windows 若隐藏扩展名，它可能显示为 **`package`**，类型为 JSON 文件。不要停留在 ZIP 压缩包内，也不要在用户主目录运行安装。
3. 在这个文件夹窗口按 **Ctrl+L**，地址栏中输入 **`powershell`**，再按回车。新打开的 PowerShell 会直接位于项目目录，不需要复制或猜测 `cd` 路径。
4. 依次输入下面三条命令；`npm.cmd ci` 完成并重新出现 `PS ...>` 提示符后，再执行启动命令。

```powershell
node --version
npm.cmd --version
npm.cmd ci
```

```powershell
npm.cmd run dev
```

看到终端中的 `Local: http://127.0.0.1:5173/` 后，在浏览器打开 **http://127.0.0.1:5173/**。保持 PowerShell 窗口打开。`npm.cmd` 与 `npm` 调用同一个 npm，使用 `.cmd` 可避免 PowerShell 对 `npm.ps1` 的执行策略限制，不需要更改系统安全策略。

首次 `npm ci` 需要联网安装依赖。安装结束后，课程、3D 几何、图标、业务规则与交互全部本地运行。系统字体由操作系统提供；没有 CDN、远程字体、模型、贴图、HDRI 或大模型接口。

### 从 v0.1 升级，保留已有记录

1. 在运行 **旧版 v0.1** 的 PowerShell 窗口按 **Ctrl+C**；如出现终止批处理询问，输入 `Y` 并回车。
2. 完整解压新版源码包，进入新版能看到 `package.json` 的目录。可以使用与旧版不同的文件夹，不必覆盖旧源码。
3. 按上面的地址栏方法打开 PowerShell，在新版目录执行 `npm.cmd ci`，安装结束后执行 `npm.cmd run dev`。
4. 用**原来的浏览器与浏览器用户配置**，继续访问 **http://127.0.0.1:5173/**。

**升级不需要清空学习记录。** v0.2 继续读取 `shouyihuo.local.v1` 和 `schemaVersion: 1`，当前尝试、已结束记录、昵称及安全错误保留。语言偏好单独保存在 `shouyihuo.locale.v1`，切换语言不会重开尝试、修改安全记录或刷新分数。记录属于浏览器访问地址，不属于源码所在的硬盘文件夹；换源码文件夹不会迁移或清除记录。

地址要完全保持一致：`127.0.0.1` 与 `localhost` 是不同存储位置；5173 与 4173 也不同。若原来使用 `localhost:5173`，请继续使用你原来的同一地址，不能切换到另一个地址后误以为记录丢失。本文其余步骤统一使用 `127.0.0.1:5173`。

### 停止与以后重新启动

停止：在运行服务器的 PowerShell 窗口按 **Ctrl+C**；如出现询问，输入 `Y` 并回车。

重新启动：用文件资源管理器打开**新版项目中能看到 `package.json` 的文件夹**，按 **Ctrl+L**、输入 **`powershell`**、回车，然后执行：

```powershell
npm.cmd run dev
```

不要每次重新安装。只有首次使用该目录、删除 `node_modules` 或更改依赖后才需要 `npm.cmd ci`。若出现 `Port 5173 is already in use`，先找到旧版或重复运行的终端，按 Ctrl+C 停止，再在新版窗口重新启动。项目开启 `strictPort`，不会静默换端口导致学习记录看似丢失；不要为了处理端口占用清空记录。

macOS / Linux：进入项目目录后使用相同命令，将 `npm.cmd` 写成 `npm` 即可。

## 2. 已实现的体验

- 课程入口：首屏同时提供认识结构、引导训练与独立测评；症状选择与后续开始按钮相邻。真实未完成尝试显示继续入口，开始新尝试保留确认。
- 真实 WebGL 3D 水箱：程序化空腔、盖、供水阀、进水管、进水机构、浮球与连杆、翻板及密封件、溢流管、水体。
- 拖动旋转、滚轮缩放、镜头范围限制、高亮与双向部件选择；支持整体视角、俯视内部和主动聚焦选中部件。
- 双击真实部件或可见标签可直接聚焦，部件列表与操作目标同步；普通单击只选择，键盘可使用「聚焦选中部件」。
- 细化水箱口沿、箱盖定位垫、安装垫圈与螺栓、进水接头、翻板转轴、真实空心管口；实例化链环与螺纹，软管纹理由内存中的程序生成，不加载外部贴图。浮球连杆围绕固定支点摆动。
- 开合箱盖、隐藏前壁、平滑爆炸视图、随部件跟随的标签与关联线；标签按视角处理出画、背面和重叠。
- 页面内放大工作区，点击「退出放大」或按 Esc 返回；保留同一尝试与 Canvas，不重开模拟计时器。
- 业务状态驱动供水阀方向、浮球高度、水位、水流、翻板开启和拆下组件的位置。
- 渲染按可见变化请求帧；镜头、水位、部件动画收敛且没有流动标记时停止持续绘制，业务模拟仍独立运行。本地程序化生成反射环境，改善陶瓷、金属与塑料的区分，不下载 HDRI 或贴图。
- 三个确定性案例：排水密封失效、进水控制失效、供水阀关闭。
- 观察、诊断、条件检查、模拟处理、复测、评分、归档的完整流程；阶段指示由真实引擎状态派生，当前阶段的主要动作突出，日志默认折叠，安全错误持续可查。
- 独立测评只给症状，首次提交诊断后才解释根因；没有联网 AI 或随机评分。
- WebGL 不可用或上下文丢失时显示清楚提示，并提供可继续规则训练的二维界面。
- `localStorage` 保存每种模式的当前尝试、已结束记录、可选昵称；继续兼容 v0.1 数据，支持刷新恢复和损坏保护。
- 报告先呈现最终判定及原因，再显示评分明细；根据真实记录给出最多 3 条复习建议，100 分但存在安全错误时明确未合格。
- 合格独立测评可打开示范完成证明，使用浏览器打印或另存为 PDF。结构认知和引导训练不生成证明。

### 工作台与 3D 操作

- 顶部「观察—诊断—处理—复测」反映实际进度，不是可以跳步的导航。提交错误诊断、拆卸被拒绝或复测失败时，界面保留真实结果；切换页签、侧栏或镜头不会补分。
- 部件首句功能说明始终显示；补充建模说明使用可键盘操作的折叠区，结构认知默认展开、计分模式默认收起。安全条件与观察操作不放进折叠区。报告用明确判定与大号分数呈现结果，100 分但有安全错误时仍显示未合格。
- 点击真实模型、部件标签或左侧部件目录可选择同一个目标；右侧说明和「操作组件」选择与之同步。普通选择不强制移动镜头，想看近处时主动点击「聚焦选中部件」。
- 「整体视角」恢复默认取景；「俯视内部」只改变镜头，箱盖需要通过「打开箱盖」操作开启。「结构剖视」隐藏前壁，「爆炸视图」仅分开展示部件，不代表已经拆卸。
- 「放大工作区」在当前页面腾出更多模型空间，不需要系统全屏权限。点击「退出放大」或按 **Esc** 返回，当前尝试、进度与安全记录保留。
- 鼠标拖动旋转、滚轮缩放。触摸界面可单指滚动页面、双指旋转和缩放；点击部件仍可选择。窄屏可通过「学习目标与部件列表」按钮展开目录。
- 查看水位、检查供水、观察部件一直可以按需进行，不需要先关水。拆卸前要满足模型的安全条件；未满足时的拆卸尝试仍会被引擎拒绝并记录安全错误。
- 复测中的阶段说明对应实际补水、稳定观察、排水和再次补水。工作状态复测通过不等同于整场测评合格，最终结果以报告为准。
- 引导训练的「学习提示」来自本地规则。独立测评在提交诊断前不显示根因、正确组件建议或待收集的特定证据清单。
- 尊重系统“减少动态效果”设置；镜头和装饰过渡减少时，水位与组件状态仍正确呈现。WebGL 降级时可以继续二维规则交互，镜头工具不可用并说明原因。

## 3. 一个完整示范路径

以下操作仅对应本项目教学模型，不是通用维修步骤。

1. 入口选择 **01 持续有水流声**，点击「开始独立测评」。想先熟悉操作，可以选择引导训练。
2. 点击「查看水位」「检查供水」。在部件目录选择「排水组件与密封件」，点击「记录部件观察」。也可以直接点击模型选择部件。
3. 在右侧「观察与诊断」页签的诊断选择框选择「排水密封失效」，点击「提交诊断」。独立测评锁定首次答案；引导模式允许重试。
4. 切换右侧「模拟处理」。依次点击「关闭供水」「检查供水」「模拟排水」，等待中央水位显示「已排空」，再「打开箱盖」。
5. 确认右侧操作组件为「排水组件与密封件」；如不是，在「操作组件」选择框切换。点击「拆卸排水组件」「模拟更换」「重新装配」。
6. 点击「恢复供水」「运行复测」。等待自动验证稳定水位，并完成一次排水后的补水循环。此时模型中的水位和浮球会实际变化。
7. 显示「复测通过」后，点击「结束并查看报告」，在弹窗中确认。首次诊断正确、证据完整、无关键安全错误且完成全部流程时为 100 分并合格。
8. 独立测评合格时可点击「生成示范完成证明」，填写可选昵称，打印。返回学习记录、刷新页面，记录仍在且不会重复。

情境 02 需要额外观察进水组件与溢流管，处理目标为进水组件。情境 03 只需观察水位、供水和进水状态，判断供水阀关闭，恢复供水并复测，**无需拆卸或更换零件**。

不要把爆炸视图当成拆卸：它仅改变呈现位置，既不增加流程分，也不改变真实装配状态。错误拆卸会被阻止，并留下关键安全错误；复位镜头、返回页面或刷新都不会清除它。重新练习会创建新编号，不会修改已完成报告。

## 4. 评分与模拟规则

| 项目 | 满分 | 规则 |
|---|---:|---|
| 证据收集 | 25 | 只计本情境的适用证据，按项分配整数分；重复观察不加分 |
| 故障诊断 | 30 | 首次正确 30；引导模式重试答对 15；独立测评锁定首次提交 |
| 处理流程 | 25 | 组件故障：隔离、确认、排空、有效处理、装配各 5；供水情境：检查 10、恢复 15 |
| 复测验证 | 20 | 完整装配、恢复供水、稳定停止进水、正常排水补水循环，各 5 |

合格要求同时满足：总分 ≥80、诊断正确、根因有效处理、组件完整装配、供水及全部工作验证完成、无关键安全错误。**即使显示 100 分，只要有关键安全错误，本次仍不合格。** 耗时只供参考，不参与评分。

水位采用归一化的教学状态，没有显示虚构的升数、压力或真实维修时间。UI 每 250 ms 发送固定时间步，纯模拟引擎内部以不超过 50 ms 的子步积分。离开工作台或浏览器标签页不可见时暂停模拟，不会在关闭页面期间偷偷完成复测。

关闭供水不会自动修好故障；更换错误部件不会清除真正缺陷；修复后仍需重新装配和复测。复测通过后再次改变供水、排水或装配状态，会使此前验证失效。

## 9. 已知限制

- 教学内容没有维修专业人士审核，零件比例、故障、水量、流量、时序均为简化；不适用于所有马桶，也不应用于现场维修判断。
- 只包含这门课程的三个确定性情境，没有真实登录、交易、派单、地图或正式认证。
- 已验证 Linux Chromium 的真实 WebGL 2（SwiftShader 软件渲染）。**未在用户的 Windows 机器或原生显卡上验证**，也未逐一验证 Safari、Firefox。
- 桌面体验优先；本轮各视口的实际检查结果和截图以测试报告为准。触摸交互实现不等于已经在所有实体手机和触控设备上验证。
- 打印媒体样式和证明内容纳入浏览器检查；实际打印机与 Windows 的 PDF 保存对话框未验证。
- Three.js 依赖在开发控制台有 `THREE.Clock` 弃用提示；构建有 Three 分包超过 500 kB 的体积提示。两者不是测试失败；本轮页面脚本错误和网络检查的实际结果见测试报告。
- 离线要求指依赖安装后的本地运行；首次下载源码、Node、npm 依赖和测试浏览器仍需要网络。
